## Próximo paso (el único bloqueo real)

Desde tu PowerShell, en `C:\Proyectos\powerfulcrm`:

```powershell
Remove-Item .git\index.lock -Force -ErrorAction SilentlyContinue
npm install
git add -A
git commit -m "feat: CSP estricto, animaciones, tests, webhook organization.created de Clerk"
git push
```

Eso sube todo a `claude/rbac-tenant-admin` (ya existe en GitHub, push normal, no toca la rama de producción protegida). Después:

1. Espera el deploy de Preview en Vercel de esa rama.
2. Abre el link de Preview y prueba el login de Clerk — es la validación real del cambio de CSP. Si el login falla, el rollback es revertir `strict: true` a `{}` en `src/proxy.ts`.
3. Configura el webhook de Clerk (Dashboard → Webhooks) apuntando al dominio de producción, como se explica arriba.
4. Cuando confirmes que el Preview está bien, avísame y hago el PR hacia `claude/multi-tenant-project-setup-vmanmh` (branch protection ya exige PR, así que no hay push directo posible aunque quisiera).

## Hallazgos extra (no en el plan original, quedan anotados)

- **CRM Kanban con drag-and-drop falso**: el texto de la UI dice "Arrastra una tarjeta para cambiarla de etapa" pero el drag real no está implementado (hay un comentario en el código confirmando que es un stub pendiente de `dnd-kit`). No lo toqué — es fuera de alcance de esta pasada, pero vale la pena decidir si lo implementas o cambias el texto mientras tanto.
- **`package-lock.json` necesita el `npm install`** de arriba para reflejar `vitest` como dependencia — no pude generarlo yo mismo (el mount de Windows no soporta las operaciones atómicas que necesita `npm install`, falla con `ENOTEMPTY`).
- **Diferencia de saltos de línea (CRLF/LF)**: en este sandbox, `git diff` muestra el archivo completo como cambiado en casi cualquier archivo del repo (incluso los que no toqué), aunque el contenido real es idéntico. Es ruido de CRLF vs LF, no un problema real — tu Git de Windows ya lo normaliza bien (por eso el commit anterior mostró solo "6 files changed", no 50). Si quieres eliminar esta fuente de confusión a futuro, un `.gitattributes` con `* text=auto` en la raíz del repo lo resuelve de forma permanente.
- **Dashboard de comparación/heatmap** y **overhead de `forTenant()`**: quedaron explícitamente fuera de esta pasada (baja prioridad / solo monitoreo), tal como se acordó.
